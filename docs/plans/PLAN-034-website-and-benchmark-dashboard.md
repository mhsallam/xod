# PLAN-034: Website and Benchmark Dashboard (separate `xod-site` repository)

- **Task ID**: `TASK-039`
- **Issue**: none (feature, not a defect)
- **Status**: Implemented (local, not deployed)
- **Repository**: `xod-site`, beside this repository - local git only at the time (since then a private GitHub repository)

## Why

The dashboard was generated by `DashboardGenerator.cs`: a 39 KB C# file that built the whole page as
one interpolated string, with CSS, JavaScript and data inside it. It was the reason the numbers had
to be typed by hand before, and it made any design change an edit to engine code.

The project also needs a landing page. Burying it in the engine repository would tie the site's
build and release cadence to a database.

## Design

Three layers with one contract between them:

| Layer | Where | Owns |
| :--- | :--- | :--- |
| Numbers | `site/src/data/benchmarks.json` (generated, committed) | medians + provenance, nothing else |
| Words | `site/src/content/metrics.ts`, `engines.ts` | names, plain explanations, technical caveats, units, direction |
| Design | `site/src/styles/app.css`, `layouts`, `components`, `pages` | tokens, layout, components |

`site/scripts/build-data.mjs` reads `benchmarks/results/*.json` from this repository and writes the
data file. It computes medians and groups; it never decides a winner, a label or a colour. The pages
derive winners from the metric direction declared in `metrics.ts`.

The only contract is the data file. The site can be rebuilt against any copy of the results
(`XOD_RESULTS` or an argument); nothing else in the engine repo is imported.

## Pages

- **`/`** — landing: plain-language statement, measured proof points (computed), a five-line code
  sample, six feature cards, a compact benchmark teaser, how to start, dark footer.
- **`/benchmarks`** — provenance strip, revision-mix warning, computed win/loss summary per suite,
  engine filter, per-suite cards of metric rows (bar + value + winner + *What this means*), method.

## Design language

Cream canvas, ink outlines at 1.5 px with hard offset shadows, Fraunces display with an italic
accent, Inter for UI, JetBrains Mono for code, amber as the single action colour, near-black footer.
Tokens live in one file so the palette and type scale can move without touching a page. Fonts are
self-hosted (fontsource), so the built site makes no external requests.

## Verification

- `pnpm build` produces two static pages; no client JS beyond the engine filter, which the page is
  complete without.
- Every number on the page comes from the data file; the summary lines are computed from medians,
  including the suites where XOD loses every metric.
- Checked visually at 1440, 520 and 390 px; the code block scrolls inside its card rather than
  widening the page.

## Deliberately not done

- **Not deployed.** The site has no remote and no hosting target yet; `dist/` is a plain static
  directory ready for one.
- **The C# generator still exists.** Removing `--dashboard` from `XodBench` is the next cleanup, so
  that there is exactly one renderer. Doing it before the site is deployed would leave the project
  with no dashboard at all.
