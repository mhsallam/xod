# XOD++ Known Issues & Legacy Design Flaws Catalog

This document tracks all known bugs inherited from XOD 1.x (`xod` / `xod.core`) as well as architectural/design issues identified in XOD++ (`xod2`). Each issue is referenced by ID in [`MASTER-TASKS.md`](MASTER-TASKS.md).

## Resolved Legacy Bugs (Phase 1 Baseline)

| Issue ID | Severity | Component | Description | Status |
| :--- | :--- | :--- | :--- | :--- |
| **ISS-001** | Critical | `XodContext.Query` / `Find` | In XOD 1.x, `query as Func<object, bool>` evaluated to `null` due to C# generic delegate variance rules, causing predicates to be ignored or throw `NullReferenceException`. | **Resolved** (`TASK-001`) |
| **ISS-002** | High | `XmlEngine.UpdateItem` / `Delete` | `UpdateItem` never set `value = true` (always returned `false`) and never fired `BeforeAction`/`AfterAction` triggers. `Delete` checked `!Root().HasElements` on `<TablePage><Rows/></TablePage>` (which was always `true`) and returned `false`. | **Resolved** (`TASK-002`) |
| **ISS-003** | High | `XmlEngine.ReservedKeyTest` | `[UniqueKey]` had a comment `// Not implemented yet` and `ReservedKeyTest` return value was ignored in `Create()`. Composite `[PrimaryKey]` properties were checked with `OR` instead of composite `AND`. | **Resolved** (`TASK-003`) |
| **ISS-004** | High | `XmlEngine.ParseChildren` & `Delete` | `ParseChildren` looked up `parentKeyPropAtt.LocalProperty` on `type.FullName` (parent) instead of `childType.FullName` (child). `Delete` called `GetPrimaryValues(type, parentValue)` instead of `GetPrimaryValues(parRefProp.PropertyType, parentValue)`. | **Resolved** (`TASK-004`) |
| **ISS-005** | Critical | `CryptoHelper` / `FileCryptoHelper` | XOD 1.x used `ASCIIEncoding.ASCII.GetBytes(key).Take(32)` and a static IV (`Take(16)`), and `CryptoHelper` concatenated decimal `byte.ToString()` instead of hex `x2`. | **Resolved** (`TASK-005`) |
